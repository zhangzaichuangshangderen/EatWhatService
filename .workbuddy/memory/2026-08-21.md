## EatWhatService：从微信云托管迁移到自建云服务（CVM/轻量应用服务器）

用户要把后端从「云托管」迁到「云服务」。核心难点是云托管会经由 `wx.cloud.callContainer`
自动注入 `X-WX-OPENID` 请求头来识别用户，脱离云托管后该 header 不再存在。

### 采用的方案（业内标准）
- 新增 `WxAuthService`：用小程序 `wx.login` 的 `code` 调微信 `code2session` 换 openid，签发 JWT。
- 新增 `AuthController.POST /api/auth/login`：入参 `{"code": "..."}`，返回 `{"token","openid"}`。
- 新增 `AuthInterceptor` + `WebConfig`：统一校验 `Authorization: Bearer <token>`，把 openid 写入 request 属性。
- 改造 `WxUserContext.resolveOpenId`：优先读 token 解析出的 openid，**兼容保留** `X-WX-OPENID` 头（过渡期双跑）。
- 业务 Controller 零改动（它们都只调用 `WxUserContext.resolveOpenId`）。
- 配置：application.yml 增加 `wx.appid/secret`、`jwt.secret/expire-hours`、`server.port=${SERVER_PORT:80}`；
  docker-compose 改为 app+mysql，app 监听 8080，新增 WX_*/JWT_* 环境变量；新增 `nginx/nginx.conf` HTTPS 反代示例；`.env.example` 补充变量；README 更新迁移说明。

### 待办（前端，不在本仓库）
- 前端仓库 `/Users/lemon.wu/Code/wechat/EatWhat` 需改：弃用 `wx.cloud.callContainer`，改用 `wx.request` 直连 `https://域名/api/...`；
  新增登录：`wx.login()` -> `/api/auth/login` 换取并缓存 token；所有 `/api/*` 请求带 `Authorization: Bearer <token>`。

### 编译/测试

## EatWhatService：新增 GitHub Actions CI/CD 自动部署

用户希望 push 到 GitHub 后自动部署到 CVM。新增 `.github/workflows/deploy.yml`：
push 到 `master`（或手动 workflow_dispatch）触发，用 `appleboy/ssh-action` SSH 登录服务器，
`git fetch + reset --hard origin/master` 拉最新代码，再 `docker compose up -d --build app`（mysql 走 volume 不动），
最后 `docker image prune -f` 释放磁盘。兼容 docker compose v2/v1。

需要的 GitHub Secrets：`SERVER_HOST`（公网 IP）、`SERVER_USERNAME`、`SERVER_SSH_KEY`（本地机器私钥，对应服务器 authorized_keys 公钥）。
服务器侧还需一把独立的 deploy key（公钥加到 GitHub Deploy keys 只读），用于服务器 `git pull`。
DEPLOY_PATH 默认 `/opt/EatWhatService`，需与服务器 clone 目录一致。

配套改动：
- `.gitignore` 增加 `.env` / `.env.*`（保留 `.env.example` 例外），避免密码误提交。
- README 新增「CI/CD 自动部署」章节；修正 API 文档开头“云托管注入 X-WX-OPENID”的旧表述为当前 token 方案。

注意区分两把密钥：`SERVER_SSH_KEY`（Actions 连服务器）与服务器 github_deploy 密钥（服务器连 GitHub）。
